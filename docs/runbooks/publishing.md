# 文章创建与检查

当前范围为 R1-02 的本地文章文件、元数据与 Markdown 校验。文章阅读路由和草稿预览尚未实现；此记录不代表网站发布流程已可用。运行证据和验收状态以 [实际验收记录](../r1-acceptance.md) 为准，精确合同见 [工程规范第 7.8 节](../../blog-r1-engineering-and-testing-proposal.md#78-补齐的内容与执行合同)。

## 创建文章

先按 [README 的环境准备](../../README.md#准备环境) 安装并启用固定工具链，在项目根目录操作。原稿、PR 和 Git 历史在公开仓库中可以被阅读；只有确认允许公开的原稿及材料才能进入仓库。`draft: true` 不能保护仓库中的内容隐私。

1. 为文章确定固定文件名，例如 `why-this-blog.md`；只使用小写英文字母、数字和单个分隔连字符，扩展名为 `.md`。文章只能放在 `src/content/posts/` 顶层，不能使用子目录或符号链接。确认目标文件不存在，再复制模板，避免覆盖现有文章：

   ```sh
   test ! -e src/content/posts/why-this-blog.md && cp templates/post.md src/content/posts/why-this-blog.md
   ```

2. 编辑新文件，填写以下四个必填字段，不增加其他 frontmatter 键：

   | 字段          | 填写规则                                                          |
   | ------------- | ----------------------------------------------------------------- |
   | `title`       | 真实标题，字符串，去除首尾空白后不能为空                          |
   | `description` | 作者确认的摘要，字符串，去除首尾空白后不能为空                    |
   | `pubDate`     | 加引号的 `YYYY-MM-DD`，必须是年 0001—9999 范围内存在的公历日期    |
   | `draft`       | 布尔值 `true` 或 `false`，新稿保持模板中的 `true`，不能写成字符串 |

   模板的空标题、空摘要和占位日期有意不能通过校验。日期只用于既定的展示与排序规则，不提供定时发布功能。

3. 用作者真实正文替换模板占位内容。文章标题已在 `title`，正文不再写 H1；第一个标题用 `##`，后续不跳级。使用普通 Markdown，不加入原始 HTML、脚本或远程图片。站内链接按工程规范写逻辑根路径，由转换器添加一次 base；不要手写 `/personal-blog/` 或链接 `.md` 原稿。附件的归属、复制和本地预览功能尚未实现，需要附件的稿件应等相应阶段完成后再验证。

4. 检查改动，确认没有误改现有文章，也没有把不允许公开的材料写入文件。改标题时保留原文件名，固定标识由文件名决定。

## 本地检查

在项目根目录依次运行：

```sh
pnpm check
pnpm build
```

全部文章和草稿都会经过内容集合校验；缺字段、未知字段、错误类型、不存在的日期、非法文件名或不合规 Markdown 会使检查或构建失败。根据日志定位文章与字段后修正，再重新运行。`pnpm build` 会清理旧输出和缓存后构建，但当前不会生成文章阅读页面、复制文章附件或部署网站。

修改内容规则或相关代码时，还可分别执行 `pnpm test:unit` 和 `pnpm test:integration`；二者已纳入 `pnpm verify:bootstrap`。提交前阶段门禁为：

```sh
pnpm verify:bootstrap
```

该门禁包含格式、lint、类型、工具链探针、文章单元与构建集成测试，以及最小首页构建和双引擎检查。它尚不包含完整文章浏览器验收、完整产物检查或线上冒烟。实际结果必须记录到验收文档，不能仅因命令存在就判定验收通过。
